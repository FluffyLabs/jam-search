# Chmod the socket and deletes images on clean up

## Pull Request by @bkchr

The socket created between the host and the fuzzer target on a rootless docker container is not accessible from the host without root. So, we now chmod the socket before using it.

Also this pull requests ensures that the image itself is deleted on clean up and not just the container.


## Comment by @davxy

Why you want to fully remove the downloaded image after each run?

Currently:
- The image is explicitly fetched via `./target.py get <target>`, so removing it prevents consecutive runs without explicit re-downloading.
- We could reasonably add automatic download when the image is missing, but forcing a re-download on every run may not be an best default?

We already provide a cleanup command: `./target.py clean <target>`.

I have also updated the script so that it now removes the Docker image as well; previously, it only removed binaries. See: https://github.com/davxy/jam-conformance/commit/1250af004a1bde53ec885e822ccc6937ff1bd8ee

If you really really want removal after a run then we may introduce a `--cleanup` flag (and also automatic download of missing images). WDYT?


## Comment by @bkchr

Fine that we use the extra `clean` cli command. Basically the idea was just to prevent "spamming" the host.
