# Fuzzer Protocol v1 extension: add feature-bundle-refinement for RefineBundle to WorkReport fuzzing

## Pull Request by @sourabhniyogi

This extends the v1 fuzzer protocol to support refinement in a way that is a major stepping stone towards JAM-NP guaranteeing with CE134 use of work package bundles
https://github.com/zdave-parity/jam-np/blob/main/simple.md#ce-134-work-package-sharing

Work package bundles with refinement context may be sent after SetState calls by the fuzzer, and the fuzzer target must return with a Work Report.  


## Comment by @sourabhniyogi

Decision required concerning whether CoreIndex and Timeslot should be included in the RefineBundle.  For simplicity, we could assume that any bundles are processed on core 0, e.g. [here](https://graypaper.fluffylabs.dev/#/7e6ff6a/2eaf002eaf00?v=0.7.1)  

At present, I kept it out, so that the fuzzer target does not have to identify itself as being part of any core, and should accept any work package bundle.  In a network setting, this is not the the case.
