# Ed25519 consensus critical test vectors

## Pull Request by @davxy

Ed25519 signature verification must be consistent across all implementations to maintain consensus. Different libraries have varying levels of strictness in validation.
These test vectors validate [ZIP-215](https://zips.z.cash/zip-0215) compliance, which defines the specific validation rules that JAM implementations must follow.

Most ed25519 libraries are **NOT** ZIP-215 compliant. If your implementation fails these tests, the underlying library likely needs updating or replacement. The fix is typically straightforward but must be done within the library itself, not by preprocessing inputs.

As ed25519 is all over the place, teams are encouraged to run these vectors against their implementation

## Identified ZIP-215 compliant libs:
- [ed25519-consensus](https://github.com/penumbra-zone/ed25519-consensus) (rust)
- [ed25519-zebra](https://github.com/ZcashFoundation/ed25519-zebra) (rust)
- [ed25519-consensus](https://github.com/hdevalence/ed25519consensus/tree/main) (go)
- [noble](https://github.com/paulmillr/noble-ed25519/tree/1ee5a2649816e3c7e08cf71905eccfbbca201b56?tab=readme-ov-file#verify) (js)


## Comment by @jaymansfield

JavaJAM was using a cryptographic library called [bouncycastle](https://www.bouncycastle.org) which rejects all of the public keys in these vectors as invalid. Due to that I was unable to try validating any of the signatures using it but I'm assuming that already means it's not ZIP-215 compliant.

So for now I've now switched to use rust's ed25519-zebra (starting in v0.3.10 of JavaJAM) until I can find a pure java solution.

## Comment by @burdges

It's obvious all nodes much use the same validation criteria.  These test vectors make batch verification work.  That's important on-chain, less important off-chain, but maybe important for bridges, RPC protocols, etc.  If for example some future bridge or RPC protocol batches together many validator signatures, then it could make batches that appear valid but containe signatures that are valid according to this criteria, but appear invalid to other ed25519 libraries.
