# Alternative approach to args decoder.

## Pull Request by @tomusdrw

It seems GP has a peculiar behaviour around parsing arguments in case we don't have enough bytes in the mask itself.

1. It make sense at the end of the program (GP says that the program is right-padded with zeros).
2. However it may happen within the program (i.e. there is not enough bytes between instructions).

AFAICT The second case can be resolved in 3 different ways:
1. Trap because the program is malformed.
2. Assume there is always enough bytes and these bytes are zeros.
3. Use the instruction bytes as arguments (but then jump to that same instruction (i.e. don't skip it)).


This PR implements option 3, as it seems that's what in the GP currently.
