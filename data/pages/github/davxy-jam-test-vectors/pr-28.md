## Comment by @arkpar

https://github.com/jam-duna/jamtestnet/blob/main/erasurecoding/src/lib.rs#L49
This does not look correct
Using `reed-solomon-simd` in a way that's compatible with GP requires splitting the data into 2 byte EC points and then transposing these into chunks as per GP (H.6) 
Additionally reed-solomon-simd requires the shards to be split into 64 byte SIMD chunks. Each SIMD chunk has all the low-order bytes of the points it contains followed by the high-order bytes.

So if the source data is 
```
v0c0l, v0c0h, v0c1l, v0c1h, ... v0cXl, v0cXh, v1c0l, v1c0h, ..., v1cXl, v1cXh, ... v341cXl, v341cXh, ...... (X = chunks). 
```
it is converted to the reed-solomon-simd input as follows:
```
v0c0l, v0c1l, v0c2l, ... v0c31l, v0c0h, v0c1h, v0c2h, ... v0c31h, v1c0l, ... v1c31h, ... v341c0l, ... v341c31h, v0c32l, v0c33l, ... v0c63l, v0c32h, v0c33h, ... v0c63h, v1c32l, ... v1c63h, ... v341c32l, ... v341c63h
```
