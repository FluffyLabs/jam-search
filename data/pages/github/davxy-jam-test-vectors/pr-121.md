# Edge-case STF vectors for disputes, authorizations and safrole

## Pull Request by @daiagi

Edge cases for GP v0.8.0, in tiny and full, each listed in its module's README.

- Disputes: a culprit is rejected when its report isn't in the posterior bad set (10.6). One vector has no verdict in the block, another has a culprit on a report judged good in the same block. A fault is rejected unless it contradicts a verdict, which can come from an earlier block (10.7). The unjudged and wonky cases are there with both votes.
- Authorizations: when the pool holds the used authorizer twice, only the left-most copy is removed (8.2, 8.3).
- Safrole: in the first block of an epoch, tickets are checked against the new ring root, with that block's offenders zeroed (6.14, 6.15, 6.32). A proof against the previous epoch's ring must fail. A ticket that wouldn't stay in the accumulator is rejected (6.36), with a new error code `useless-ticket (7)` in `safrole.asn` and `safrole.py`.


Question: `votes` is declared as `SEQUENCE (SIZE(0..validators-super-majority))` in `lib/jam-types.asn` (line 621), but the GP doesn't bound it. 10.2 leaves the judgments unbounded, and 10.4 asks for exactly ⌊2|k|/3⌋+1 judgments of whichever set signs, current or previous. Since 0.8 the set size can change between epochs, so that count isn't fixed. Only `validate.py` checks the bound, and the binary decodes longer lists fine, but a vector with a larger verdict fails validation. Should the bound be dropped?
