## Comment by @sourabhniyogi

@davxy I understand this is a WiP but we would like to have our jamtestnet "state transition" and "state snapshots" attribute names and structure modeled as close as possible if not identical to those you have here and elsewhere in the STFs, where the `service` JSON format is great!  But there is one little detail concerning `code_image` [example](https://github.com/davxy/jam-test-vectors/blob/cbaa3fc09430097fa3a067fbec52a8ad131c50f8/accumulate/tiny/enqueue_self_referential-2.json#L260)-- I believe we would like just a `preimages` array with the `code_image` eliminated and instead just present in a `preimages` array:

```
...
        "preimages": [
          {
            "hash": "0x2823707a8588a068e2ce8d8d3e790de3d0f0efd12988f848a8b9731004d44b16",
            "blob": "0xbc07000000000000002..."
          },
          {
            "hash": "0x7a71eb4834e36bcea488abf607e408569bd27cab1ca9c6075f4a4cf64d0a6048",
            "blob": "0x31237cdb79ae1dfa7ffb87cde7ea8a80352d300ee5ac758a6cddd19d671925ec973d6a912166c954916057eb6a07d3e8bf"
          }
        ],
...
```
See [this](https://github.com/jam-duna/jamtestnet/issues/38) for the above in context.

We would like to cover ALL 4 components -- including [a_s](https://graypaper.fluffylabs.dev/#/4bb8fd2/384e03384e03) even though it "won't scale" as @gavofyork says, for the purpose of us being able to being able to compare state roots with 100.0000000% of the service `data` while the state snapshots are still small enough to put into github repos -- if you have an example with a_s (k,v) for us to follow that would enable us to follow your JSON structure perfectly.
