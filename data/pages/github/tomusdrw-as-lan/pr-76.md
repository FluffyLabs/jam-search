<p>The rule detects implied <code>eval()</code> usage through functions like <code>setTimeout</code>, <code>setInterval</code>, and <code>setImmediate</code> when called with string arguments.</p>
<pre lang="js"><code>// Invalid

<p>// Valid
setTimeout(() =&gt; alert(&quot;Hello&quot;), 100);
</code></pre></p>
</li>

<p><a href="https://redirect.github.com/biomejs/biome/pull/9320">#9320</a> <a href="https://github.com/biomejs/biome/commit/93c3b6ca52d4966db2c5b9c37d73c049ffccd1a5"><code>93c3b6c</code></a> Thanks <a href="https://github.com/taberoajorge"><code>@​taberoajorge</code></a>! - Fixed <a href="https://redirect.github.com/biomejs/biome/issues/7664">#7664</a>: <a href="https://biomejs.dev/linter/rules/no-unused-variables/"><code>noUnusedVariables</code></a> no longer reports false positives for TypeScript namespace declarations that participate in declaration merging with an exported or used value declaration (<code>const</code>, <code>function</code>, or <code>class</code>) of the same name. <li>
<p><a href="https://redirect.github.com/biomejs/biome/pull/9216">#9216</a> <a href="https://github.com/biomejs/biome/commit/04243b0535dfb65fd106f5a760ab24668786dcaf"><code>04243b0</code></a> Thanks <a href="https://github.com/FrederickStempfle"><code>@​FrederickStempfle</code></a>! - Fixed <a href="https://redirect.github.com/biomejs/biome/issues/9061">#9061</a>: <code>noProcessEnv</code> now also detects <code>process.env</code> when <code>process</code> is imported from the <code>&quot;process&quot;</code> or <code>&quot;node:process&quot;</code> modules.</p>

</li>
<li>
<p><a href="https://redirect.github.com/biomejs/biome/pull/9627">#9627</a> <a href="https://github.com/biomejs/biome/commit/06a0f351d4885385f90f64604b6f391e5012f2c3"><code>06a0f35</code></a> Thanks <a href="https://github.com/ematipico"><code>@​ematipico</code></a>! - Fixed <a href="https://redirect.github.com/biomejs/biome-zed/issues/191">#191</a>: Improved the performance of how the Biome Language Server pulls code actions and diagnostics.</p>
<p>Before, code actions were pulled and computed all at once in one request. This approach couldn't work in big files, and caused Biome to stale and have CPU usage spikes up to 100%.</p>
<p>Now, code actions are pulled and computed lazily, and Biome won't choke anymore in big files.</p>
