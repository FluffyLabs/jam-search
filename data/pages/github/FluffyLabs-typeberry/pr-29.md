# Initial state trie

## Pull Request by @tomusdrw

This PR adds:
1. Parsing of the trie tests JSON format.
2. Implementation of the state trie, including constructing the trie nodes and calculating the root.
3. The trie can be later updated in an optimal fashion (no re-hashing of all the leaves).
4. The trie uses a store that I think will be optimal for on-disk storage (i.e. we keep store `<hash> -> <node>` mapping on disk so it's possible to only fetch the nodes on-demand).
5. Adds `blake2b` library (with WASM support). Initially I wanted to use `node-blake2` but it was failing to compile with recent node versions (v22), so resolved to `blake2b` which is probably slower, but should run fine in the browser.
6. I'm trying to avoid re-hashing the nodes, but that causes and edge case when we move a leaf from left branch to right branch (left branched nodes hashes are 1 bit shorter).

Some potential improvements:
1. Change the way we `insert/remove` nodes from `NodesDb` - instead of doing it right away we can instead produce a changeset that can be applied independently (although that could also be done on the `NodesDb` abstraction itself (like `startTransaction` or sth)
2. Avoid re-hashing the leaf when it's moving from left to right.
3. Implement a proper `Map` to store `Bytes`. Currently it's using a stringified form, which is extremely sub-optimal.

The implementation passes all currently available tests at https://github.com/w3f/jamtestvectors/pull/2
