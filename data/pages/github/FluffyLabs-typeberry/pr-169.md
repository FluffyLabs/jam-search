## Comment by @tomusdrw

So we don't necessarily close the connection, we just close the stream. Also we do close it one way.
Imagine that the sender is not following the protocol, but rather keeps sending us some blocks all the time. As soon as we receive our response we should not receive anything else here and if someone attempts to send something we need to indicate that this is something that is not conforming to the protocol.

Everything we write here has to work in adversarial conditions - i.e. the other party can do nasty stuff just to attempt to crash our node (for instance trigger out of memory).

So as soon as something is wrong we need to throw an exception and that will be handled in another layer and for instance:
1. Add the peer that has been sending us incorrect data to some sort of "banned list" so that we don't allow them to connect to us in the future.
2. Disconnect the peer right away on ALL streams (not just the one in failure).
3. etc.
