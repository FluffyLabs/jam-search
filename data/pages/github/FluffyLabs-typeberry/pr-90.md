# PVM: memory implementation

## Pull Request by @mateuszsikora

# What
This PR introduces new memory implementation that is GP-compatible. This implementation is consistent with memory definition in PVM and also allows to handle memory segmentation (SPI) efficiently.

# Why it is needed?
The previous implementation was wrong despite it passes all available tests.

# Basic assumptions:
1. It should allow to make a single memory cell readable/writeable
2. It should allow to work with whole memory pages
3. The initialisation process is not needed - programs should be able to allocate memory on they own
4. Memory can be easily initialised using `MemoryBuilder`
5. Reading and writing operations don't allocate any memory - they take result array to fill as a param

# How it works?
By default the memory is empty and a program can use `sbrk` to allocate memory (default sbrk index is 0). It is also possible to prepare memory before program execution and pass it as `initialState` param of PVM constructor (it will be changed, see "next steps"). The initial memory can be created using `MemoryBuilder` class. It is possible to use memory chunks smaller than page size using `setReadable`/`setWriteable` methods and also you can use whole pages by using `setReadablePages`/`setReadablePages`. At the final step you have to set `sbrkIndex` and `endHeapIndex` index - they are `finalize` params. The space between those indexes has to be empty and will be used by `sbrk` instruction.

# Next steps:
- add possibility to re-use PVM instance (https://github.com/FluffyLabs/typeberry/issues/75)
- adjust PVM interface to be compatible with https://github.com/FluffyLabs/typeberry-toolkit/issues/81
