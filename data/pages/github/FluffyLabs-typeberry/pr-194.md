# `Machine` + `Peek` + `Poke`

## Pull Request by @tomusdrw

A set of 3 closely-related and pretty simple host calls.

1. `Machine` - starts a new PVM instance and writes the assigned "MachineId" to the register.
2. `Peek` - copy a fragment of a running PVM instance into our local PVM.
3. `Poke` - write a fragment of our local PVM into a running PVM instance.

The actual copying does not happen inside the host calls, due to how `Memory` access is restricted. Since we can only `loadInto` or `storeTo` I didn't want to create an intermediate object that will be used to copy the data.

Also I didn't want to expose a `Memory` instance of the inner PVM to the host call directly, because most likely we will be able to optimize the copying better closer to the actual running instance especially in case we switch to Rust-based PVM (for instance directly invoking some sort of `memcpy`). I'm not super convinced to this API, but having it implemented like we currently have allows us to defer that decision until we know things better in the future.

## Comment by @tomusdrw

Migration from 32-bit -> 64-bit is a one-off operation. Exactly the reason for using `U32` in API is to have it show errors when you try to assign `U*` into `U32`.
We still need to decide if we are going to use `bigint` to represent the `U64` in 64-bit PVM or some custom type, but in both cases it should display errors due to `number <> bigint` mismatch.
