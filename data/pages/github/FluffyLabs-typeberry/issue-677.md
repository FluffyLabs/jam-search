# Improve efficiency of `ServicesUpdate`

## Issue by @tomusdrw

`AccumulationStateUpdate` contains changes generated by current accumulation run. That includes also updates to the services, encapsulated as `ServicesUpdate`, see:
https://github.com/FluffyLabs/typeberry/blob/4ae774ab24c4d15d84456914d5d8e80d0c49c346/packages/jam/jam-host-calls/externalities/state-update.ts#L51

All updates to services are currently stored in a flat arrays, and every time we do a lookup, we need to find the exact entry we are interested in ([example](https://github.com/FluffyLabs/typeberry/blob/main/packages/jam/jam-host-calls/externalities/state-update.ts#L155)).
With small amounts of updates this is good enough, but when there is many services and/or many storage items updated the performance might degrade due to linear lookups.

We should consider storing this data more efficiently. For instance:
1. Separate updates between services and store that as `Map<ServiceId, ...>`.
2. Use `HashDictionary` (or some similar structure, where `BytesBlob` can be a key) to manager storage updates.
3. Preimages are probably fine flat, if they are separate by `ServiceId`.

Potentially related: #36
