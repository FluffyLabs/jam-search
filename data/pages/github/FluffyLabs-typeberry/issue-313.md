# Optimize bandersnatch wasm calls

## Issue by @tomusdrw

It seems that calling into `batch_verify_tickets` and `verify_seal` from bandernsatch library is pretty slow (around 125ms, even if we don't verify anything).

I'm assuming it's not really a cost of purely invoking some WASM, but rather it's probably an verifier initialisation:
https://github.com/FluffyLabs/bandersnatch/blob/main/src/lib.rs#L334

- [ ] Note that the verifier may only change in the input keys change (i.e. once per epoch), so it makes a lot of sense to somehow persist that structure between runs (wasm global = Rust's lazystatic)?
- [x] Another issue is that calling into WASM is not really parallelizable. Even though we have multiple tests running they all seem to depend on each other when calling into the same WASM module. I'm assuming this is an issue with the wrapper generated by `wasm-pack`, where we just have one WASM module instance. Instead we should consider creating a couple of instances (with background worker threads) and dispatch the calls between them asynchronously.
