# Introduce nested packages

## Pull Request by @tomusdrw

This PR partially resolves #10. I've noticed that `npm` introduced `workspaces` so I've decided to use that instead of switching to `pnpm` completely.

If we ever run into issues with pure `npm` or if there are any advantages of using `pnpm` I'm happy to work on that further.

So far it seems that the main goals of what we need are achieved:
1. The dependencies can be defined more locally, next to the package that needs them.
2. We use scoped names for self-contained packages.
3. We can reference code from other packages just like if they were a separate dependency (i.e. `@typeberry/bytes` vs `../bytes`).
4. `npm ci` installs all deps of the sub-packages as well.
5. Every packages has a `test` command, so you can easily run tests just from a single package. (It's a bit of copy-paste code now - any ideas how to avoid that welcome)

Closes #10 (As mentioned earlier `pnpm` can be introduced separately if really needed).
