# Re-work codec views.

## Pull Request by @tomusdrw

This PR contains significant changes around codec Views.

1. `View` now has it's own descriptor. So it's possible to `encode/decode` the view, or use the `View` explicitly as part of the structure that you create (so you can ensure that some stuff ALWAYS decodes, while other things are materialized).
2. Some of the primitive types have their views associated with them as well. For instance `u64` can always be viewed as `Bytes<8>`.
3. Nested views are properly typed now. There is no need to list "fields with nested views" as previously.
4. When decoding `View` we actually validate that the encoding is structurally sound (because we skip the view). Previously we were just wrapping the bytes with view, but there was no guarantee that there is even enough bytes inside.
5. `SequenceView` was added, which allows lazily-decoding the collections. As seen in the benchmark there is a huge performance improvement there.
6. I fixed `cast` function (actually removed it) in favour of `asOpaque` which is more strongly typed.
7. `SizeHint.bytes` is now required. It was pretty much filled everywhere and there was no point of making it optional. One can always specify `{bytes: 0, isExact: false}` as an equivalent (see `codec.custom` default).
