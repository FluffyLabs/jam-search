# Add benchmarks

## Pull Request by @tomusdrw

Resolves #2 

Initially I've started working on a logger, but pivoted into writing some benchmark code :)

This PR introduces a framework based on [`benny`](https://www.npmjs.com/package/benny#code-reuse) that allows creating benchmarks.

Some details on how to create benchmarks can be found [here](https://github.com/FluffyLabs/typeberry/blob/0141bd0ff96201c5c02a64ac36879caee846c5bf/benchmarks/README.md), but in short:
1. You create one or many `.ts` files with a bunch of tests inside (just like JS Perf / JS benchmark)
2. We run all benchmarks (from all suites) using `npm run benchmarks` command.
3. On top of just running benchmarks, the command produces a summary of all suites (That can later be posted as a PR comment via github action).
4. For some suites one can also create an expected results file, which is compared to the current execution. In case there is a significant divergence (defined by `margin`) in the results - the GH Job will fail and the error summary will be posted in the GH comment.

So we can use the benchmarks both to compare some JS approaches, but also to make sure that our changes do not break the existing optimisations of some performance-critical code.
