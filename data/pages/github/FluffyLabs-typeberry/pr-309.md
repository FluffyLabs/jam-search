## Comment by @tomusdrw

Please avoid `as` casting. IMHO it's totally broken in typescript and should be forbidden. I'd even consider adding some eslint rule if there is one.
Like `as WhateverType` should always be interpreted as `as any as WhateverType`, because the compiler is doing such minimal checks between the two types that it more often gets in the way than helps.

In that particular case, there is no guarantee that `e` is going to be of type `Error` so it's incorrect in general case.

I'd rather go for something like:
```ts
type InvalidProgramError = {
  details: string;
};
...
return Result.error({ details: `${e}` });
```

## Comment by @tomusdrw

I'd move `deblob` into `machineInit` and have it return a `Result` instead. The reason for that is that now we have to do the same thing twice:
1. We `deblob` here just to check validity
2. Then we `deblob` inside the `machineInit` to actually execute the code.

Since you allow passing any `BytesBlob` as parameter to `machineInit` it's not really clear how it should behave if a non-deblobable code is passed (i.e. you can't even start a machine, so you can't assign it a `machineid`), so that's another argument for why `deblob` should be done internally.
