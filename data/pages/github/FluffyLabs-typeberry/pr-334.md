# Make `Opaque` types more strict.

## Pull Request by @tomusdrw

It seems that the typescript compiler becomes pretty lazy when it comes to `never` types. It can happily assign `never` to ANY type that is on the other side, so in our case we had a bunch of errors that were caused by using `asOpaqueType` which was basically casting to any type on the left hand side.

This PR introduces a new `Uninstantiable` type that we resolve `Opaque` to. That makes the compiler a bit less lazy (or actually a bit more strict), and requires us to pass the target types explicitly.

I think this is worth it though, since it can save us time in the future when debugging.
