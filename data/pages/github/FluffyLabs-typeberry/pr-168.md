# Disputes

## Pull Request by @mateuszsikora

This PR introduces Disputes implementation and closes https://github.com/FluffyLabs/typeberry/issues/158

The solution is inspired on `Safrole` class (the state is passed via constructor and `transition` function that have whole logic). The order of items is important (and test vectors check it ) so I added `SortedSet` collection that is used to keep disputes records. Unfortunately I cannot use it in test runner because it would change the order of items in expected state / output. This is why I had to add logic to transform `DisputesState` into `TestState`.

Signature verification is currently a performance bottleneck but the code is ready to replace `@noble/curve` with some Rust library. My first idea was to collect whole data that needs verification in one array but maybe it would be better to have 3 separate arrays (culprits, faults and judgements) and await verification promise in verify functions (next to the usage).

We have to merge [test vectors](https://github.com/FluffyLabs/jamtestvectors/pull/4) before we merge this PR

So let me make sure that I understand what you are doing here:
1. You have a bunch of entries in `disputes.culprits`, these entries contain `workReportHash` (Bytes<32>), `key` (also `Bytes<32>`, unique & sorted) and `signature` (`Bytes<64>`).
