# Codec Validation & Improvements

## Pull Request by @tomusdrw

Closes #253 


### Verification ❌
After working on this PR I've decided that doing verification directly in the codec is not a good idea.
This PR implements codec descriptors for some of the data types that do require some checks (like `KnownSizeArray` or `HashDictionary`), however we I think now that we should know follow in-codec verification.

Main reasons:
1. The code may become pretty convoluted, and where the checks are happening is really unclear.
2. It's not clear whetever we should perform validation only for materialized structures or for views as well. It may lead to weird situation where we skip a bunch of fields to encode some other field, while these skipped fields would fail verification.
3. With the current design there is no way to get detailed error code as of why the validation failed.
4. Detailed error codes are needed to maintain JAM test vectors compatibility.

Instead I think we should rather extract common verification logic and for instance perform that logic on data views AFTER we decode the view/structure as we do currently.

### Other additions
1. Codec for `HashDictionary` and usage of that struct to swipe the optimisation todos.
2. Improve context-dependent codec definitions
3. Fix views of `codec.select` and `codec.custom`. Unfortunately the type system in TypeScript was not good enough to catch the errors in the type definitions there (antoher reason to avoid complicating codec even more).
