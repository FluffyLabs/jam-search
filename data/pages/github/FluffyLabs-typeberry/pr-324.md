# Codec/JSON block importer

## Pull Request by @tomusdrw

Related #311 

It doesn't fully close the issue, since it would be cool to merge it with #308 to make sure it works correctly.
Also note there is no state storage here yet or genesis initialisation.

However it works currently and is able to read and "import" bin and JSON blocks from jamduna test vectors, so leaving it for a review already.

To read JSON blocks I had to extract the whole `fromJson` stuff from the test runner into a separate package called `block-json`.

Next steps:
- [ ] genesis init
- [ ] state read/write
- [ ] actual stf (needs #308)

## Comment by @tomusdrw

Our pipeline is designed for blocks that we get from the network, or encoded using codec (i.e. much more compact representation than JSON). Because of that we expect `BlockView` which is a thin wrapper around encoded bytes and we can use lazy-decoding.

However, since JSON files are present in some of the test repos, I think it's still valuable to be able to import them, since they are more human-readable and can potentially be modified easier. But when we read json we get `Block` (materialized data structure). To turn it into `BlockView` we need to encode the `Block` and then turn the encoded data into `BlockView`. Note that even though we use `Decoder` to get `Block.Codec.View` back, it's a very cheap operation, I just wanted the API to be consistent between materialized structures and `View`s`.
