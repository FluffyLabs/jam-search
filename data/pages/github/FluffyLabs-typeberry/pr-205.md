# 64 bit PVM

## Pull Request by @mateuszsikora

# What?
This PR changes PVM interpreter to be aligned with GP 0.5.0:
- 64 bit registers / opcodes
- Page size 4096 
- Access type for whole pages instead of single bytes

# Changes in packages

## @typeberry/pvm-interpreter
1. Modify Instruction list
2. Changed `Registers` API to hide internal implementation 
3. Changed `Registers` implementation to use `BigUint64Array` / `BigInt64Array`
4. Added 64-bit variants of function in `math-utils.ts`
6. Added `unsignedRightShiftBigInt` to `math-utils.ts` because `>>>` does not exist on `bigint`
7. Added stuff to handle 64 bit immediate in args (instruction `LOAD_IMM_64`):
  - `ArgumentType.ONE_REGISTER_ONE_EXTENDED_WIDTH_IMMEDIATE` arg type
  - `OneRegOneExtImmDispatcher` 
  - `OneRegisterOneExtendedWidthImmediateArgs`
  - `ExtendedWitdthImmediateDecoder` 

8. `DynamicJumpOps` - extract address calculation from `jumpInd` to a separate method (`caluclateJumpAddress `) because of the corner case in `LOAD_IMM_JUMP_IND` when it uses the same register 
9. Removed `VirtualPage`
10. Page size changed to `4096`
11. `MemoryBuilder`:
 - Removed `setWriteable` because `VirtualPage` is removed (9.)
 - Removed `setReadable` because `VirtualPage` is removed (9.)
12. Added `setData` to all memory pages (it is useful to create `Memory` instance from test vectors)

## @typeberry/test-runner
- Added `json-bigint-patch` to read 64 bit registers in pvm test vectors 
- Changed register types from 32 to 64 bit 

## @typeberry/pvm-debugger-adapter
- registers API adjustments because of 2. and 3.

## @typeberry/pvm-host-calls
- registers API adjustments because of 2. and 3.

## @typeberry/pvm-host-calls-jam
- registers API adjustments because of 2. and 3.
- test data changed because of 9. and 10.

## @typeberry/pvm-spi-decoder
- Registers adjustment because of 2. and 3.
- page size changed
