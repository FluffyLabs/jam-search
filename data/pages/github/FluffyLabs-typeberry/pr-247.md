# Updating links to the newest version.

## Pull Request by @tomusdrw

I've manually went through all the links that `links-check` proposed and fixed the ones that were broken.
I'm not sure if we really should be doing that though, it seems that there were some links that didn't indicate they were broken, yet they were pointing to a completely unrelated part of the GP. I guess that's something to be fixed in the tool.

However, if the tool is reliable and we perform these migrations, I'd like to propose the process for this:
1. After this PR all notes will be in exact same versions.
2. When new GP is out, we can prepare a PR like that as soon as possible.
3. Any changes/broken links should be added as new issues.
4. We might consider adding some sort of `//ignore` flag to the links, so that in places where the code does not match the latest GP we keep the old version.

Alternatively we may only update the links, when someone is working/updating some code - i.e. you touch a file containing links, you should migrate them to the newer versions (and review the results). Not sure however if that will be enforceable.

## Comment by @mateuszsikora

Personally I don't like the idea to update all links at once. The problem is that some code was written based on GP in version `x` and this functionality may be changed in version `x + 1`. So auto-update can cause discrepancies between the code and GP. I think it would be nice to have numbers of formulas in the comments and then based on the information if a formula was (or wasn't) changed from version `x` to `x + 1` update the link. If the formula was changed then it would be nice to keep old link and add some comments that it needs manual work 


## Comment by @tomusdrw

Yes, I think having code aligned with GP is definitely better than having recent links (but broken). In theory the update mechanics should be much more biased towards not having false-positives as outlined here: https://github.com/FluffyLabs/graypaper-reader/issues/157

So in case the link checkers says: "broken link" that should be an indication that something in the Gray Paper definitely has changed.
But there is also an issue with what the link is pointing to - if you select a fomula, then it will check the formula, but if it's just a link to the section name then it's unlikely that any changes in that section will be noticed. So I think we both agree that it might actually be the best idea to just keep the old links the whole time in the future and use the `links-check` tool to just get a potential list of things that MUST have changed in the GP, hence the code needs a review/update.
