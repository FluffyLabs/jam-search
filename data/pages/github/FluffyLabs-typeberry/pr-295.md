## Comment by @tomusdrw

I strongly feel that `machines` should not be exposed. The logic of how to run the machine should be hidden behind the `externalities` interface and not done inside the host call implementation.

Initiating a machine is simple now, but when we get to the compiler part it will be much more complicated. Also the code of the machine is likely going to be large, so there is no point of passing it back and forth in memory.
We basically should just say: "invoke machine of index `machineIndex`" and nothing more. The internals should figure out if there is an already running instance that we can re-use or if we should start a new one by fetching the code from the database, etc.

I understand this design is closer to what's stated in the GP, but in that particular instance it's just going to be impractical.


## Comment by @tomusdrw

All of this should not be controlled by the host call, but rather by the internals of invocation.

## Comment by @tomusdrw

My suggestion was to not make it a default on purpose. There is a significant difference here.

If you add another `Status` and have a `default` branch it will simply fall into the `default` branch. We don't want that. We rather want the compiler to display an error and force the developer to handle that status.

However in reality (aka runtime) we might get something that isn't a `Status` at all and that's why I'd rather have an `Error` in such cases to make it easier to debug (i.e. after the switch)
