# `Historical Lookup` + `MultiMap`

## Pull Request by @tomusdrw

I've implemented the first Refine-stage host call: Historical Lookup. The code for the host call & tests is basically a copy&paste of the regular lookup, except:
- the host call index
- the external function we are calling `account.lookup` vs `refine.historicalLookup`.

I'd prefer to avoid abstracting out this duplication for now (and possibly for ever). We might sneak in the `timeSlot` directly to the host call implementation (instead of having it be impilcit to the externalities implementation) and then the two would diverge even further and the abstraction would probably do more bad than good.


Given that there isn't that much new code in the PR I decided to bundle together the `MultiMap` implementation.

In couple of host calls tests already there was a need for having a map that has values indexed by two keys. It was solved by `Map<..., HashDictionary<...>>` because the second key happened to be a hash.
In this PR I've changed the old cases and replaced everything with `MultiMap`, which is basically a nested maps implementation for arbitrary number of keys.

Since `Map` only works with primitive types, for complex key types there is an option to provide a `keyMapper` which changes the complex object into something that can be easily compared by value instead of reference.

Note that the `MultiMap` might not be particularly performant, but it's a good enough structure for tests, since it also allows dumping the entire content to compare the results.


Related: #36 
After some slight alterations (namely changing `KeyMapper` to be able to return multiple primitive values instead of one for a complex object) we could potentially implement an efficient `HashDictionary` by splitting the hash object into `4 x number`. Or we might also decide to implement `HashDictionary` as `MultiMap<[number, number], OpaqueHash[]>` and just use 2-number prefix and then an array for resolving collisions depending on the number of items in the dictionary.
