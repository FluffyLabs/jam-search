# Block pruning

## Pull Request by @tomusdrw

To support long running fuzzer sessions, where we don't care that much about history, but we are simply growing the one canonical chain, this PR implements a block pruning mechanism. 
`BlocksDb` and `StatesDb` are now effectively becoming a sliding window when running in memory.

NOTE: I expect we might still be leaking a bit of data, due to values db never being cleared (since it would need to support ref-counting), but it might work good enough for now.
