## Comment by @tomusdrw

Note this code does not enforce ordering and that's actually needed:
<img width="917" alt="image" src="https://github.com/user-attachments/assets/b63f9616-be8e-4bd2-af48-3202f1f663ca" />

For both ordering and no duplicates the code can actually be "simpler", because you don't need to build up the set.
```ts
/** Compare two byte vectors in a lexicographical order. */
function isGreaterOrEqual(a: BytesBlob, b: BytesBlob) {
  const len = Math.min(a.length, b.length);
  for (let i = 0; i < len; i += 1) {
    if (a[i] === b[i]) {
      continue;
    }
    return (a[i] > b[i]) ? true : false;
  }
  // we assume that if the second argument is longer (other things equal) it's actually greater than `a`.
  if (b.length > len) {
    return false;
  }
  // `a` is longer than `b` or completely equal.
  return true;
}

let lastServiceId = -1;
let lastBlob = BytesBlob.blobFrom(new Uint8Array());
for (const preimage of input.preimages) {
   if (lastServiceId > preimage.requester) {
     return Result.error(...);
   }
   if (lastServiceId === preimage.requester) {
     if (isGreaterOrEqual(lastBlob, preimage.blob)) {
       // within the same service id, the blobs need to be ordered.
       return Result.error(...);
     }
  }
  lastServiceId = preimage.requester;
  lastBlob = preimage.blob;
}


## Comment by @tomusdrw

The state will need to be encoded into JAM codec and stored in the database. Dictionary encoding is actually `[key, value][]` where the array is sorted by the `key`.
Here `HashDictionary` is fine, since we will most likely be able to decode that from a sorted array.

However the `Map<AccountsHistoryKey, HistoryItem>` is not something that we will be able to support.
Please change it to something like:
```ts
// docs: https://graypaper.fluffylabs.dev/#/5f542d7/116f00116f00
type PreimageRequested = FixedSizeArray<TimeSlot, 0>;
type PreimageAvailable = FixedSizeArray<TimeSlot, 1>;
type PreimageUnavailable = FixedSizeArray<TimeSlot, 2>;
type PreimageReavailable = FixedSizeArray<TimeSlot, 3>;

type PreimageStatus = PreimageRequested | PreimageAvailable | PreimageUnavailable | PreimageReavailable;

type HistoryItem = {
  hash: PreimageHash;
  length: U32;
  status: PreimageStatus;
};

// ordered by `hash`
history: HistoryItem[];
```

Alternatively you can have `HashDictionary<PreimageHash, { length: U32, status: PreimageStatus }>`. There is no way you can have preimages with different lengths and the same hash.
