# Move core data to the model.

## Pull Request by @tomusdrw

This PR moves the structures prepared earlier in #130, specifcally only for JSON deserialization to it's own package `@typeberry/block`.
This new package is a basis for our data model that will be used to build the rest of the client. The JSON serialisation stays in the test-runner for now (we don't want it in the model).

The model, however contains JAM-codec details. So each class now has `Codec` object attached and can be read from bytes (or encoded to them). The model objects follow typescript idiomatic conventions (so `camelCase` instead of `snake_case` in JSON), and the conversion is handled by the JSON serializer/deserializer objects.

I've also implemented the code for all of the codec tests, where we read the JSON file read the `.bin` file and compare the deserialized and decoded data, but also compare that the encoding we produce matches the one in `.bin`.

One annoyance that I've noticed is that the model (or rather encoding/decoding) is dependent on some global context object that was used to create the test cases.
For instance: to decode `Verdict.votes` we need to know EXACTLY what's validators super majority. For the test cases it's `5` but for the production network it will rather be somewhere around `768`. This extra data is passed as a context object to `Encoder` and `Decoder`, and later we dynamically decide how to decode the data based on the required context information. This is done via `codec.select`.

What's left is docs & GP references, but I'm intending to do that in a separate PR.

## Comment by @tomusdrw

Yes, `HeaderHash` is just an `Opaque<Bytes<32>, ...>`, while `Opaque` is basically the same underlying type with some extra "identification string" attached to it.

The `.cast()` function only converts to subtypes of `Bytes<32>`, so there is no way you accidentally cast from `number` to `Bytes<32>` or sth like this.

I think putting `HeaderHash` there would be redundant - IMHO there isn't any value in discrimining between variants of `Bytes<32>` on the codec level - it's the data model (i.e. `AvailabilityAssurance` class) that defines what type `anchor` is, the code is just describing how it's stored.
