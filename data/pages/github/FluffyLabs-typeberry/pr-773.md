# Fix in-memory serialized states

## Pull Request by @tomusdrw

As detected by our typeberry-testing suite, the recently released 0.3.0 version was failing minifuzz tests (note to self, we should run these tests pre-release, but that's already noted in https://github.com/FluffyLabs/typeberry-testing/issues/34)

This PR fixes fork handling, by copying the leafs of the state BEFORE updating the state. Otherwise we were altering the previous state data and because it was stored in-memory it was also the entry in the `db` collection being updated.

## Walkthrough

The PR updates state-update flows in three modules. In database-lmdb/states.ts and database/serialized-states-db.ts, after successful updateAndCommit the code now constructs a new LeafDb from current/updated leaf collections and calls state.updateBackend to refresh the backend, and serialized-states-db clones the leaf set before updating to avoid mutating the original. In workers/importer/importer.ts the post-update DB fetch and backend update are removed; subsequent logic now uses the in-memory state for computing stateRoot and continuing epoch preparation.
