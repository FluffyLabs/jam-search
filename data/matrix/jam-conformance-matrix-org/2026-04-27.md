@room in order to streamline targets submission and execution in the upcoming web app, we will require targets to be packaged within a Docker image.
Some of you are already doing this. 
For those currently providing a plain binary, the transition should be straightforward: considered that currently we simply run your binary inside a **vanilla debian-lite** container, you mostly need to extend that image and include your binary within it.
Another improvement will be the standardization of the entry point and args. I will open a discussion in the jam-conformance repository about this, but the intended direction is for targets to support a super small set of options, such as:
* spec=full/tiny: to run the target with either full or reduced jam parameters. Whether this is internally implemented via separate binaries or a single binary with CLI arguments is internal to your image.
