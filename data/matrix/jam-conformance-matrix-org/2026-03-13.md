**jan** (2026-03-13T06:06:00.000Z) [msgid:$49cj1QKcPwGG2ZjYUKKZzbYWDTXMgbFW74-aXKpZ190]:
PVM would be completely unusable in a GPU context.

In general doing compute on a GPU is an entirely different beast, and would require a very different approach. Some points off the top of my head:

- GPU compute is inherently non-deterministic.
- GPU capabilities vary very strongly between different hardware; for CPUs their behavior, architecture and instruction sets are somewhat standardized and consistent (even between different vendors), while for GPUs that is not true even within a single vendor
- Real world GPU workloads (e.g. in ML) often require a ton of persistent memory which needs to be attached to a single node for a considerable amount of time to make any useful progress (otherwise you'll be spending the vast majority of your time shuffling data around the network and not doing any useful work)
- At least for machine-learning workloads, you probably wouldn't need gas metering because all of the types of kernels used in practice are essentially bounded when it comes to how much compute they're doing, and I think you might get away with just having a kernel verifier plus calculating the cost empirically.
- High end GPU hardware is much more expensive than high end CPUs, and it's not just a simple "better hardware == faster compute, but you can still do the same compute on any hardware, just slower". You need higher end GPU hardware for some types of compute, otherwise you just can't run the workload at all (well, in theory you can, but the speed difference would be multiple orders of magnitude, which makes it practically useless)

That said, the biggest challenge with GPU compute is, probably, the determinism issue. Unlike with a CPU-based VM you can't just validate the output of a computation and check whether it's bit-by-bit the same.
