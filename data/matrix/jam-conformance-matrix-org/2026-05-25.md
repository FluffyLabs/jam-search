Writing this here since the other channel is busy with the fuzzying/conformance testing.

I was asked about this in the past before, and recently it has become increasingly clear as to what we'll be requiring of your PVM implementations for future milestones, so here's a small FYI: while the clean room implementation rules for the JAM prize do not change, you are allowed to look at the exact machine code that other implementations emit (but only in a black-box fashion!) and generate similar machine code in your implementation without being penalized (so e.g. you can use my polkatool disassemble and look at what exact machine code that prints out, and even if you mimic that you won't be penalized).

The reason for this is that, at least for JAM 1.0, the new gas cost model and the upcoming gas metering of the paging mechanism itself will de facto require very specific machine code to be generated which is at least as efficient as what the gas cost model assumes. It would be silly to force everyone to reverse engineer this from the GP (especially since for a lot of instructions there isn't really a lot of wiggle room as to how they can be translated into machine code). I will most likely also write an unofficial reference document with "baseline" native machine code lowerings for each PVM instructions to make things easier (so you'll be required to emit code which is at least as efficient as what's written there).
