**danicuki** (2026-05-21T09:56:00.000Z) [msgid:$epSHhAkIdesAmH3QdPuKk_43IbqWLa0qAMUInd6S-1I]:
I understand the fuzzer is not meant to be a debugging utility.

But even as a gate, the current ordering creates avoidable dead time. If a team fails L2b, the next useful signal is whether L2b still fails. Running L2a first does not make the L2b signal stronger; it only delays it.

I am not proposing to reduce coverage or reuse previous results. The final pass should still require all phases to pass in the current run with fresh seeds.

The proposal is only:

1. On retry, run the last failed phase first.
2. If it fails, stop and report.
3. If it passes, continue with the rest of the phases, including earlier ones.
4. Only accept the submission if all phases pass in that run.

That preserves the integrity of the check while making the submission loop much more practical for teams.
