**dave** (2025-12-02T00:38:00.000Z) [msgid:$nAO13pvr0mgg7HjNDCiuYaI0paIaOlqB1lSKwlJ0LDk]:
Not sure about having an implementation identifier as it may encourage people to make decisions based on it. For how bad this can get see eg the User-Agent header.

Re identifying features I'm not sure if that makes sense for validators specifically. Validators are supposed to all do the same job, and eg cores rotate around them frequently.

In the case of the existing JIPs, whether a validator node implements these or not is only really of concern to the node operator, not to anyone else. JIP-1 should not be enabled on a real validator node; it is for debugging only and enabling it on a real node is almost certainly a security issue (the fixed gas charge is unlikely to be sufficient to cover the actual cost of logging). JIP-2 should _never_ be publicly exposed as it requires the two sides to trust each other. If enabled on a real validator node JIP-3 should only connect to a private telemetry server, it really is not safe to send that information to a third party. It also probably doesn't make sense to do that anyway as it would use a big chunk of your bandwidth.
